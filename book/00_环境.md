# 第 0 章 环境：先把地基打对

## 本章要解决什么问题

这一章不训练任何模型。它只回答一个问题：**你的 GPU 是真的能用吗？**

听起来像是废话 —— `torch.cuda.is_available()` 打印一个 `True` 不就完事了？但本书恰恰是从一个「打印 `True` 但其实不能用」的环境开始的。而且它的坏法非常刁钻：连矩阵乘法都能跑，你一碰卷积才炸。

如果你跳过这一章直接开始写模型，你会在第 3 章第一次搭 CNN 时遇到一个看不出所以然的报错，然后花一整天怀疑是自己的代码写错了。所以先把地基验一遍。

---

## 0.1 conda 环境：为什么不用 base

Anaconda 装好之后，默认那个环境叫 `base`。很多人图省事，所有包装在 base 里。**不要这么做。**

原因是深度学习项目的依赖很容易打架：这个项目要 PyTorch 2.8 + CUDA 12.8，那个项目要 PyTorch 1.13 + CUDA 11.7，两个版本的 `torch` 包会互相覆盖。一旦 base 被搞乱，你连 conda 自己的命令都可能跑不起来，最后只能重装 Anaconda。

正确的做法是**一个项目一个环境**：

```bash
# 创建（本书的环境已经建好了，这里只是说明它从哪来）
conda create -n pytorch python=3.9
conda activate pytorch
```

本书使用的环境：

| 项 | 值 |
|---|---|
| 环境名 | `pytorch` |
| 解释器路径 | `C:\Users\ASUS\.conda\envs\pytorch\python.exe` |
| Python | 3.9.25 |

<blockquote class="tip">

**💡 提示**

用 `conda env list` 可以列出所有环境。带 `*` 的是当前激活的。
你所有实验都请在 `pytorch` 环境里做，不要用 base。

</blockquote>

3. 点齿轮图标 → `Add...`
4. 左侧选 `Conda Environment`
5. 选 `Existing environment`，在 `Interpreter` 里填：

6. 确定。之后 PyCharm 右下角应当显示 `Python 3.9 (pytorch)`

**验证方法**：在 PyCharm 里新建一个文件，写上你自己的验证代码（下面 0.4 节会给出），直接运行。如果它能打印出版本号，说明解释器配对了。

<blockquote class="warn">

**⚠️ 常见坑**

## 0.3 `is_available()` 的陷阱（本书的第一个教训）

先看一段代码。这是很多人装完 PyTorch 后写的第一行验证：

```python
import torch
print(torch.cuda.is_available())
```

它打印了 `True`。于是你以为环境没问题了。

**但 `True` 只说明两件事**：

1. 驱动能看到一块 NVIDIA 显卡；
2. 你装的这个 `torch` 是 CUDA 版本，不是 CPU 版本。

它**没有**说明你的显卡真的能在这套 PyTorch 上执行运算。本书的环境就是活生生的反例。下面是当时的真实自检输出（完整文件见 `results/env_before.txt`）：

```
--- 1. 版本与可见性 ---
Python     : 3.9.25
torch      : 2.8.0+cu126
CUDA(build): 12.6
is_available: True                                    ← 说能用
device     : NVIDIA GeForce RTX 5060 Laptop GPU
capability : (12, 0)  -> sm_120 (Blackwell)

--- 2. 这个 torch 编译覆盖了哪些算力 ---
arch_list: ['sm_61', 'sm_70', 'sm_75', 'sm_80', 'sm_86', 'sm_90']    ← 没有 sm_120

--- 3. 逐算子实测（每个算子独立进程）---
  matmul               OK                             ← 居然是能跑的！
  Linear               OK
  ReLU                 FAIL  CUDA error: no kernel image is available...
  Conv2d forward       FAIL  CUDA error: no kernel image is available...
  Conv2d backward      FAIL  CUDA error: no kernel image is available...
  MaxPool2d            FAIL  CUDA error: no kernel image is available...
  BatchNorm2d          FAIL  CUDA error: no kernel image is available...
  AdaptiveAvgPool      FAIL  CUDA error: no kernel image is available...
  CrossEntropy         FAIL  CUDA error: no kernel image is available...
  softmax              FAIL  CUDA error: no kernel image is available...
```

**这张表才是真相**：`is_available()` 说能用，`matmul` 也确实能跑，但只要你碰一下卷积、ReLU、池化，立刻失败。

<blockquote class="done">

**📌 结论**

`is_available()` 返回 `True` **不等于** GPU 真的能算。
这句话请你记牢 —— 本书后面的每个章节脚本都用同一个模式来选设备：
先问 `is_available()`，**再跑一次真实算子**，两者都通过才用 GPU。

</blockquote>

### 为什么会这样

一句话解释：**你装的这个 PyTorch 在编译时，没有把你这张显卡的算力编进去。**

PyTorch 的 CUDA 版本是用 C++/CUDA 写的，编译时会针对一批显卡架构分别生成机器码，这批架构就是上面那个 `arch_list`。运行时，PyTorch 会找与当前显卡匹配的那份。找不到匹配的，就报：

```
CUDA error: no kernel image is available for execution on the device
```

本机的情况：

- 显卡是 RTX 5060 Laptop，属于 NVIDIA 的 Blackwell 架构，算力 **sm_120**；
- 装的 `torch 2.8.0+cu126` 最高只编到 **sm_90**（上一代 Hopper）；
- `arch_list` 里没有 sm_120 → 大部分算子没有可执行的机器码 → 失败。

那为什么 `matmul` 和 `Linear` 又能跑？因为它们底层走的是 **cuBLAS**（NVIDIA 官方的矩阵运算库），cuBLAS 自带一套备用路径，恰好能凑合执行。而 ReLU、卷积、池化这些是 PyTorch 自己写的 CUDA kernel，没有备用路径，直接失败。

<blockquote class="warn">

**⚠️ 常见坑**

这正是这个 bug 最阴险的地方：坏得**不彻底**。
如果你只用 `is_available()` 验证，或者随手跑了个 `x @ y` 看到成功，
你会得出「环境没问题」的结论，然后在几小时后搭 CNN 时才撞墙 ——
那时你早已忘了环境这回事，只会觉得是自己的代码写错了。

**教训：验证要覆盖你真正要用的操作。** 矩阵乘法通过，不代表卷积通过。

</blockquote>

## 0.4 怎么真正验证 GPU 能用

记住这个模式，本书每个章节脚本都用它：

```python
def cuda_really_works():
    try:
        conv = nn.Conv2d(1, 4, 3).cuda()
        x = torch.randn(2, 1, 28, 28, device="cuda")
        y = torch.relu(conv(x))
        torch.cuda.synchronize()      # ← 这一行不能省
        return True, f"卷积前向成功，输出形状 {tuple(y.shape)}"
    except Exception as e:
        return False, str(e).splitlines()[0]
```

三个要点：

**第一，探测要覆盖你真正要用的操作。** 这里探测的是卷积 + ReLU，因为这是本书要用的东西。用 `matmul` 探测会漏报（0.3 节的血泪）。

**第二，`torch.cuda.synchronize()` 不能省。** CUDA 是**异步**执行的：你调用一个算子，Python 这边立刻返回，真正的计算在 GPU 上排队。如果不开同步，算子里出的错**不会在那一行抛出**，而是被推迟到后面某个完全无关的地方才爆 —— 那时你看堆栈会一头雾水，指向一个根本不相关的函数。

```python
# 不开同步：报错可能出现在这里，跟真正出错的地方毫无关系
y = conv(x)          # ← 真正出错的是这一行
z = y + 1
print(z.sum())       # ← 错误可能在这里才抛出来
```

`torch.cuda.synchronize()` 强制等 GPU 把所有排队的活干完，错误就会在正确的位置抛出。

**第三，降级到 CPU 时不要静默。** 如果 GPU 用不了，脚本会自动用 CPU 继续跑 —— 但一定要**打印出原因**。否则你会以为自己在用 GPU，实际在用 CPU，然后纳闷为什么训练这么慢。

## 0.5 随机种子：设了到底有没有用

深度学习里到处是随机：权重初始化、数据打乱、Dropout。为了结果能复现，我们固定随机种子：

```python
def set_seed(seed: int) -> None:
    random.seed(seed)              # Python 标准库的 random
    np.random.seed(seed)           # NumPy
    torch.manual_seed(seed)        # PyTorch 的 CPU 随机数
    torch.cuda.manual_seed_all(seed)  # PyTorch 在所有 GPU 上的随机数
```

四行分别管一个随机数来源，**少一行就会有某个环节不受控**。比如你只设了 `torch.manual_seed` 而漏了 `np.random.seed`，那么任何用 NumPy 做的数据增强都是随机的。

设完之后，同一份代码跑两次结果完全一致：

```
两次 set_seed(42) 后的 torch 随机数是否一致: True
两次 set_seed(42) 后的 numpy 随机数是否一致: True
```

**但种子不是万能的。** 它能保证的只是：**同一台机器、同一份代码、同样的库版本**下可复现。以下情况结果仍会不同：

- 换了机器或换了显卡
- 升级了 PyTorch / cuDNN 版本
- cuDNN 自动选择了不同的卷积算法（同一个问题可能有多种实现，哪个快用哪个，而它跑 benchmark 的过程本身带随机性）

所以：**不要指望用固定种子让不同环境的结果对齐**。它的用途是让你在调试时能重现自己的实验，仅此而已。

<blockquote class="tip">

**💡 提示**

如果你确实需要**严格**可复现（比如要复现一篇论文的数字），可以再加：
```python
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```
代价是训练会变慢，因为放弃了 cuDNN 的算法自动寻优。本书默认不开，
因为在学习阶段「跑得快」比「严格可复现」更重要。

</blockquote>

## 0.7 常见坑汇总

<blockquote class="warn">

**⚠️ 常见坑**

**1. 只看 `is_available()` 就以为环境没问题。** 这是本章反复强调的，因为代价最大。

**2. 忘了 `torch.cuda.synchronize()`，报错位置完全对不上。** 你会在一个无辜的函数里看到 CUDA 错误。

**3. PyCharm 的解释器和命令行不是一回事。** 命令行 `conda activate pytorch` 装好了包，PyCharm 用的可能是另一个解释器。设置见 0.2 节。

**4. 在 base 环境里装包。** 见 0.1 节。污染 base 之后连 conda 自己都可能罢工。

**5. Windows 上中文输出乱码。** Python 在 Windows 默认用 GBK 编码输出，中文会变成 `CNN ǰ��+����` 这种样子。解法是在脚本开头加：
```python
import sys
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8")
```
本书所有脚本都带了这三行。

**6. 安装 PyTorch 过程中 `import torch` 突然失败。** 这不是坏了。pip 装大包时会先卸载旧的再装新的，中间有个短暂窗口 `torch` 目录不完整，报 `OSError: [WinError 126] ... caffe2_nvrtc.dll`。**等 pip 跑完再试**，不要以为装坏了去重装。

</blockquote>

## 小结

- `torch.cuda.is_available()` 返回 `True` 只说明驱动能看到卡、装的是 CUDA 版，**不代表算法能跑**
- 真正验证要**跑一个你实际会用到的算子**（本书用卷积 + ReLU），并加 `torch.cuda.synchronize()`
- 本机的病根是：`torch 2.8.0+cu126` 只编到 sm_90，而 RTX 5060 是 sm_120。换成 cu128 版本即可
- 坏的征兆可能**不彻底**（matmul 能跑、卷积不能），所以验证要覆盖真实操作
- 随机种子保证同环境可复现，不保证跨环境一致
