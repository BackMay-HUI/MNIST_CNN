# 第 4 章 数据增强

## 本章要解决什么问题

前三章一直在用原始的训练集。这一章给训练图**随机动一点手脚**（转个角度、挪一挪、擦掉一块），看会发生什么。

结论先放在最前面，因为它和很多教程讲的不一样：

- **轻增强把测试集从 98.60% 抬到 99.03%**，但换几个种子之后，这个涨幅**和随机波动差不多大**（第 4.4 节有完整数据）。
- **强增强反而把准确率打掉了 1.59 个百分点**（97.01%）—— 增强不是越强越好。
- **翻转类增强在 MNIST 上是纯粹有害的** —— 因为翻转之后标签就错了（4.3 节有图）。

所以本章真正的重点是这句话：**数据增强不是一个"涨点开关"，它是在给训练集加难度。** 有没有用、有多大用，取决于你的模型本来有没有在死记硬背。

---

## 4.1 增强解决什么问题

先看一个现象。第 3 章训练到第 10 轮时：

```
    6 |     0.0315   99.02% |    0.0595  98.42% |
    7 |     0.0258   99.20% |    0.0618  98.38% |
    8 |     0.0212   99.33% |    0.0601  98.38% |
    9 |     0.0194   99.37% |    0.0614  98.41% |
   10 |     0.0168   99.44% |    0.0579  98.48% |
```

**训练集准确率还在涨**（99.02% → 99.44%），**验证集准确率却卡住不动了**（98.42% → 98.48%，四轮只涨了 0.06 个百分点）。

这就是**过拟合**：模型开始"背题"了。它在训练集上越做越对，但这份进步没能迁移到没见过的图上 —— 它记住的是这 60000 张图的**具体样子**，而不是"数字长什么样"这个规律。

数据增强的思路很直接：**如果模型能背下这 60000 张图，那就别让它看到一模一样的图。** 每张图在送进网络之前随机变一点点 —— 这次转 7 度，下次转 -3 度；这次往左挪 2 个像素，下次往右挪 1 个。

于是同一个数字，模型一辈子也见不到两次完全相同的版本。它被迫去抓**更本质的东西**（"这一横在上面"），而不是记住像素。

<blockquote class="tip">

**💡 提示：增强是在"造数据"，但造得很有分寸**

严格说，增强并没有产生新信息 —— 它只是把已有的图变换了一下。但它的作用是真的：

- 它告诉模型**哪些变化是不重要的**。"5 稍微转一点还是 5"，这条信息是靠"同一张图给我看它转过的样子，标签仍然是 5"传达的。
- 换句话说，增强是在**把你自己知道的先验知识喂给模型**：平移、旋转不该改变类别。

这也是为什么 4.3 节要讲翻转 —— 一旦你喂进去的先验是**错的**，增强就从帮忙变成捣乱。

</blockquote>

## 4.2 为什么只对训练集做

这是本章最重要的一条纪律，没有例外：

**训练集增强，验证集和测试集永远不增强。**

道理其实很朴素：

- **增强是训练手段，不是数据本身。** 它的目的是让训练更难、逼模型学得更好。
- **验证集和测试集的职责是"考试"。** 考试要考的是"模型在真实数据上表现如何"。如果连考卷也被随机改过，那你测出来的分数到底代表什么？改一次考卷分数变一次，这个分数就没法用来比较任何东西了。
- 更具体地说：**验证集的分数要用来做决策**（"这轮比上轮好吗？""这组超参比那组好吗？"）。如果验证集每次都因为随机增强而抖动，这些决策就全成了抛硬币。

本章的脚本把这个纪律做进了**函数签名**里，不靠注释提醒：

```python
def get_loaders(batch_size, limit=0, seed=42, train_tf=None):
    # 验证/测试永远用最朴素的 transform —— 没有旋转、没有平移、没有擦除
    eval_tf = get_aug_transform("none")
```

注意它**只接受一个 `train_tf`**，评估用的 transform 在函数内部写死。你就算想给验证集加增强，**也没有参数可传**。这样"不小心给验证集加了增强"这个错误在结构上就不可能发生。

（如果写成 `get_loaders(train_tf, eval_tf)` 两个参数都能传，那迟早有一次会传错。让错误无法表达，比写一句"请注意别传错"可靠得多。）

<blockquote class="warn">

**⚠️ 常见坑 1：`random_split` 之后，验证集偷偷带上了增强**

这是本章最容易踩、而且**不报错**的坑。

`random_split` 切出来的子集，**继承的是原 dataset 的 transform**：

```python
full_train = datasets.MNIST(..., transform=train_tf)   # 带增强
train_set, val_set = random_split(full_train, [50000, 10000])
# ↑ val_set 现在也带增强！因为它指向同一个 dataset 对象
```

程序照跑不误，只是你测出来的验证集分数**每次都不一样**，而你不会知道为什么。

本章脚本的解法是切完之后显式换掉：

```python
val_set.dataset = datasets.MNIST(str(DATA), train=True, download=True, transform=eval_tf)
```

（`random_split` 返回的子集只记了"我要原 dataset 的第几号到第几号"，所以换掉 `.dataset` 就换掉了整条 transform 流水线。）

</blockquote>

## 4.3 `transforms` 家族逐个讲

`torchvision.transforms` 里全是这种"输入一张图、输出一张图"的小工具。串起来用：

```python
tf = transforms.Compose([
    transforms.RandomRotation(degrees=10),      # PIL 图上做
    transforms.RandomAffine(degrees=0, translate=(0.1, 0.1)),
    transforms.ToTensor(),                      # 到这里变成张量
    transforms.Normalize((0.1307,), (0.3081,)),
    transforms.RandomErasing(p=0.5),            # 张量上做
])
```

### 顺序不是随便排的

上面这段的顺序有讲究，两条规则：

1. **`RandomRotation` / `RandomAffine` 必须在 `ToTensor` 之前。** 它们在 **PIL 图像**上操作 —— 那是数据还是"图片"格式的时候。放到 `ToTensor` 后面也能跑（torchvision 支持张量输入），但那时数据已经变成 0~1 的浮点张量，几何变换要先转回去再转回来，容易出意料之外的结果。
2. **`RandomErasing` 必须在 `ToTensor` 之后。** 它要往图上"抹掉一块"，操作的是张量。
3. **`Normalize` 放在增强和 `RandomErasing` 之间。** 也就是增强作用于原始像素，`RandomErasing` 作用于标准化之后的值。

第 3 条有个直观后果，看后面 4.4 节图 4-2 里那些**灰块**：`RandomErasing` 默认填 `value=0`，而它执行时数据已经标准化过了 —— 0 代表的是"像素值等于训练集均值 0.1307"，还原回来看就是一块**灰色**。如果它排在 `Normalize` 之前，0 就是纯黑。

**同一个参数，位置不同，结果不同。** 这就是为什么流水线的顺序要当成代码的一部分来读。

### 本章用到的，和没用的

| transform | 干什么 | 本章用在哪档 |
|---|---|---|
| `ToTensor()` | PIL 图 → 张量，顺便把 0~255 压到 0~1 | 全部（必需） |
| `Normalize(mean, std)` | 减均值、除标准差 | 全部（必需） |
| `RandomRotation(degrees)` | 随机转 `±degrees` 度 | light（±10°）、strong（±30°） |
| `RandomAffine(degrees, translate, scale)` | 仿射变换：平移 / 缩放 / 旋转 / 错切，一次配齐 | light、strong |
| `RandomErasing(p)` | 以概率 `p` 抹掉一块矩形 | strong（`p=0.5`） |
| `RandomHorizontalFlip()` | 随机左右翻转 | **本章禁用**，见下 |
| `RandomVerticalFlip()` | 随机上下翻转 | **本章禁用**，见下 |
| `RandomCrop` / `RandomResizedCrop` | 随机裁剪一块 | 没用（见 4.5 节） |
| `ColorJitter` | 改亮度 / 对比度 / 饱和度 / 色相 | 没用（MNIST 是灰度图，没有颜色可调） |

`RandomAffine` 的参数值得单独说一句，因为它一次能配好几件事：

| 参数 | 含义 | `translate=(0.1, 0.1)` 是什么意思 |
|---|---|---|
| `degrees` | 旋转角度范围 | 这里写 0，表示不旋转（旋转交给 `RandomRotation`） |
| `translate` | 平移幅度，**按图像宽高的比例算**，不是像素 | 最多挪动宽/高的 10%，即约 2.8 个像素 |
| `scale` | 缩放范围 | `(0.9, 1.1)` 表示缩小到 90% ~ 放大到 110% |
| `shear` | 错切（把矩形推成平行四边形） | 没用 |

**`translate` 是比例不是像素**，这点容易记错 —— 28×28 的图上 `translate=(0.1, 0.1)` 只挪不到 3 个像素，肉眼几乎看不出来。想让它明显一点，就得往大了调。

### MNIST 上的陷阱：翻转类增强有害

网上讲数据增强的文章，几乎都会推荐 `RandomHorizontalFlip`。**在 MNIST 上千万别用。**

看一眼图 4-1：

![翻转为什么在 MNIST 上有害](../figures/ch04_flip_trap.png)

*图 4-1：原图、水平翻转、垂直翻转并排对照（都取自 MNIST 测试集真实图片）*

- **「2」水平翻转后**是一条反向的 2 —— 现实中根本没人这么写，它不对应任何一个数字。
- **「5」「7」水平翻转后**同理，都变成了不存在的形状。
- **「6」垂直翻转后**变成了一个看起来像「9」的东西。**这才是最危险的情况**：图变了，标签还是 6，等于你亲口告诉模型"这个像 9 的东西是 6"。

所以翻转在 MNIST 上不是"收益小"，而是**actively 有害** —— 它在教模型学错的东西。脚本里索性不提供这两个 transform。

<blockquote class="tip">

**💡 提示：判断一个增强能不能用，只问一个问题**

**"这张图变换之后，标签还对吗？"**

- 手写数字转 10 度 → 还是同一个数字，标签对 ✓
- 手写数字左右翻转 → 标签错了 ✗
- 车牌识别里左右翻转 → 车牌不会左右颠倒，标签错 ✗
- 病理切片旋转 90 度 → 还是同一块组织，标签对 ✓
- 交通标志上下翻转 → "靠右行驶"翻过来意思就反了 ✗

这个判断不需要任何数学，只要你了解**你的数据在现实中会怎么变化**。这也是数据增强最需要"人"的一步 —— 库只提供工具，用哪个得你自己定。

</blockquote>

## 4.4 三档增强的真实对照

脚本提供三档强度（`--level none|light|strong`），定义都在 `get_aug_transform()` 里：

| 档位 | 做了什么 |
|---|---|
| `none` | 什么都不做（`ToTensor` + `Normalize`） |
| `light` | `RandomRotation(10)` + `RandomAffine(0, translate=(0.1,0.1))` |
| `strong` | `RandomRotation(30)` + `RandomAffine(0, translate=(0.2,0.2), scale=(0.9,1.1))` + `RandomErasing(p=0.5)` |

`strong` 到底有多"强"，看图 4-2 最直观 —— 同一张「5」，8 次采样：

![同一张图的 8 次强增强](../figures/ch04_aug_grid.png)

*图 4-2：同一张原图经过 8 次强增强。注意有几张里出现了灰色矩形 —— 那是 `RandomErasing` 挖掉的区域*

### 10 个 epoch，种子 42，实测结果

```
增强            训练集      验证集      测试集     过拟合gap
--------------------------------------------------------------
不增强        99.44%   98.48%   98.60%      0.96%
轻增强        97.79%   98.74%   99.03%     -0.95%
强增强        86.12%   96.84%   97.01%    -10.72%
```

（完整日志就是你跑练习 1 时 tee 出来的 `results/ch04_full.txt`，同一份数据在同目录的
`ch04_compare.csv`。`results/` 是**本地产物目录，不随仓库分发** —— 按练习 1 那条命令跑一遍就有了。）

![三档增强的验证集曲线](../figures/ch04_compare.png)

*图 4-3：三档增强的验证集损失（左）与准确率（右）*

逐条读这张表：

**① 轻增强：涨了 0.43 个百分点。**

98.60% → 99.03%。听起来不错，但先别急着下结论 —— 见下一小节。

**② 强增强：掉了 1.59 个百分点，而且训练集准确率崩到 86.12%。**

这一档要特别注意最后那个数字：**训练集只有 86.12%**。也就是说，模型**连训练集都拟合不了了**。

第 3 章那个不增强的模型，训练集能到 99.44%。强增强之后掉到 86.12% —— 因为训练图被转 30 度、挪 20%、还随机擦掉一块，**难度已经超过这个 4 层小网络的容量**。它学不动了。

这就是"增强不是越强越好"的实测形态：**增强强度和模型容量必须匹配**。数据被搞得越难，模型就得越强才能学会；模型不够强，你只是把训练任务搞得没法完成。

**③ 三种情况下的训练耗时差很多。**

```
不增强   3.7 ~ 3.9 秒/epoch
轻增强   6.2 ~ 6.9 秒/epoch
强增强   8.3 ~ 8.5 秒/epoch
```

增强是在 CPU 上逐张图做变换的，**不增强时 GPU 根本喂不饱**（3.7 秒里大部分时间在等数据之外）。加了增强，每个 epoch 的预处理时间直接翻倍。这是增强的真实成本，调参时得算进去。

### 那 0.43 个百分点，是真的吗？

第 3 章 3.7 节已经测过：**同一个模型换个随机种子，准确率会在 98.29% ~ 98.72% 之间波动，跨度 0.43 个百分点。**

而轻增强的涨幅正好是 0.43 个百分点。**这就必须追问了** —— 万一是种子抽得好呢？

于是把轻增强换 4 个种子各跑一遍（同样 10 个 epoch）：

| 种子 | 不增强（第 3 章实测） | 轻增强（本章实测） |
|---|---|---|
| 0 | 98.29% | **99.03%** |
| 1 | 98.72% | **98.61%** |
| 2 | 98.47% | **98.83%** |
| 42 | 98.60% | **99.03%** |
| **平均** | **98.52%** | **98.88%** |
| **区间** | 98.29% ~ 98.72% | 98.61% ~ 99.03% |

（不增强那一列就是第 3 章的 `--init kaiming` 四个种子 —— 本章 `none` 档的种子 42 结果 98.60% 和第 3 章**逐行完全一致**，可以确认是同一套配置。）

**结论是：平均涨了 0.36 个百分点，但两个区间是重叠的**（98.61% ~ 98.72% 这段两边都有）。轻增强最差的一次（98.61%）落在不增强的区间内。

所以诚实的说法是：

- **平均而言，轻增强确实更好**（4 个种子全都 ≥ 不增强的平均值）。
- **但单看准确率，这个提升幅度和随机波动是同一量级**，用一次运行的结果去宣称"增强让我涨了 0.43 个点"是站不住的。

<blockquote class="tip">

**💡 提示：准确率之外，还有一个更能说明问题的信号**

再看一眼那条**验证集曲线**（图 4-3 右）：

- **不增强**：第 6 轮达到 98.42% 之后就**平了** —— 第 10 轮才 98.48%，四轮涨 0.06 个百分点。而同期训练集从 99.02% 一路涨到 99.44%。**这就是过拟合的样子**：训练集在涨，验证集不动。
- **轻增强**：第 6 轮 98.38%，第 10 轮 98.74% —— **还在涨**。

（第 1 轮两者几乎一样：96.68% vs 96.60%。**增强并不会让模型起步更快**，它的作用在后面才显现 —— 当不增强的模型开始"背题"的时候。）

**这就是增强真正在起作用的地方**：它没有把准确率顶上去多少，但它**让模型晚了很久才开始过拟合**。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 2：拿"过拟合 gap"跨配置比较**

本章汇总表里那列 `过拟合gap`（= 训练集准确率 − 验证集准确率），**不能跨行比较**。

原因：不增强时，训练集准确率是在**原始图**上算的；加了增强之后，训练集准确率是在**被转过、挪过、擦过的图**上算的。**输入都换了，两个数还怎么比？**

所以：

- 轻增强那行 gap 是 **-0.95%**（负的），**不代表"没有过拟合"** —— 它代表"训练图现在比测试图更难"。
- 强增强那行 **-10.72%** 也是同样的道理，只是差距被拉得更大。

**能跨行比较的只有两列：验证集准确率和测试集准确率** —— 这两列的输入对所有档位都是同一批、未被增强的图。

要用 gap 判断过拟合，得把训练集准确率在**干净的训练图**上再算一遍。本章没做这一步，所以正文的结论只建立在验证集 / 测试集上。

</blockquote>

<blockquote class="done">

**📌 结论：为什么增强在 MNIST 上收益有限**

本章实测：轻增强平均 +0.36pp（且区间与不增强重叠），强增强 **−1.59pp**。也就是说，**"加了增强就涨点"在这份数据上不成立。**

原因有三条，都很具体：

**① 手写数字的姿态变化本来就小。**

数据增强是在告诉模型"哪些变化不影响标签"。但这个信息**只在数据里真的存在这种变化时才有用**。自然图像里的一只猫，可以有无数种姿态、角度、遮挡；而 MNIST 里的数字，是几百个人**规规矩矩写在方框里**的 —— 变化的空间本来就窄。

**② MNIST 已经做过居中归一化。**

这是最容易被忽略的一条。原始的 NIST 数据里，数字的位置和大小是乱的；而 MNIST 的制作者已经把每个数字**裁剪出来、等比缩放、居中放进 28×28 的画布**。

所以"平移"这个增强，**MNIST 的制作者已经用预处理做了一遍**。你再随机平移，等于把已经对齐好的图又推歪 —— 收益自然小。（本章 `translate=(0.1, 0.1)` 只挪不到 3 个像素，也是因为这个。）

**③ 模型本来就没怎么过拟合。**

不增强的模型 gap 只有 **0.96%**（训练集 99.44% vs 验证集 98.48%）。**能压的空间本来就只有这么大。**

这一点最关键。增强的收益不是恒定的 —— 它正比于"模型本来过拟合得有多厉害"：

| 场景 | 典型的 gap | 加增强的效果 |
|---|---|---|
| 本章：4 层 CNN + 60000 张 MNIST | 0.96% | 很小（+0.36pp，噪声量级） |
| 大网络 + 500 张图 | 可能 20%+ | **往往很明显，几个百分点起** |

**所以正确的做法是：先看你的 gap，再决定要不要加增强。** gap 很小的时候，把精力花在别处（换结构、调学习率）更划算；gap 很大的时候，增强是性价比最高的一招。

**"不是所有数据集都适合增强"——这句话比"增强总是有用"更有价值。** 库给你的是工具，用不用、用多强，得看你的数据。

</blockquote>

### 两张永不加后缀的图

第 2 章定下的规矩：非正式运行产生的图要加后缀，免得盖掉书里的正式图。

但本章有两个例外：`figures/ch04_aug_grid.png` 和 `figures/ch04_flip_trap.png` **永远不加后缀**。因为它们的内容**跟训练完全无关** —— 只画增强效果，跑 1 个 epoch 和跑 10 个 epoch 出来的图一模一样。

判断标准是：**这张图的内容依赖训练结果吗？** 依赖（比如准确率曲线）就加后缀，不依赖就不加。

### 什么算"正式运行"

书的图会被后来的人反复重跑，所以得先回答一个问题：**哪些产物是"书里引用的那一份"，不许被别的运行盖掉？**

本章的答案写成一个函数：

```python
# 书上那条命令的完整取值 —— 每个能改变产物的开关都在这里判一遍
CANONICAL = dict(epochs=10, limit=0, seed=42, batch_size=128, lr=0.01)

def is_canonical(args) -> bool:
    """这次运行是不是"书上写的那条命令"（三档全跑 + 所有开关都是默认值）。"""
    return (not args.smoke) and args.level is None and all(
        getattr(args, k) == v for k, v in CANONICAL.items()
    )
```

只有它为真，才允许写 `figures/ch04_compare.png` 和 `results/ch04_compare.csv`。其它跑法统一加后缀：

```
--smoke                → ch04_compare_smoke.png
--epochs 3             → ch04_compare_e3.png
--level light          → ch04_compare_light.csv
```

**为什么要判断"是不是书上那条命令"，而不是"是不是冒烟"？**

因为"冒烟"太窄了。本章开发过程中就吃过一次亏：为了验证结果可复现，用 `--epochs 1` 连跑了两次 —— 它**不是冒烟**，于是顺理成章地写进了 `ch04_compare.png`，把书里的 10 轮对比图悄悄换成了 1 轮版本。

所以判断标准是：**这次运行的产物，是不是书上要引用的那一份？** 是，才用正式文件名。

### `--seed` 为什么也在表里

上面那张表把 `seed` 也列进去了，但**本章没有任何一条命令会因为种子而写错文件** —— 练习 3 虽然换了种子，却顺带带了 `--level light`，被 `args.level is None` 挡掉了。

那为什么还要查？因为**"碰巧被别的参数挡住"不是安全，是运气**。定稿验收时统计了一下：第 4 章的这个判断漏了 `seed` / `limit` / `batch_size` / `lr` 四个开关，其中三个当时没被任何一条命令触发。判断条件该覆盖"哪些参数能改变产物"，而不是"哪些参数恰好被练到了"。

配套的可执行检查是 `tests/test_canonical_guard.py`：每个开关都是一个用例，漏了就会红。

（同一个坑在本书里出现过三次：第 2 章的单档曲线、第 3 章四种初始化互相覆盖、本章的这两处。**凡是"生成的文件会被书引用"，都要问一句：别的运行会不会把它盖掉？**）

## 常见坑

<blockquote class="warn">

**⚠️ 常见坑 1：`random_split` 之后验证集带上了增强**

见 4.2 节。不报错，只是验证集分数开始随机抖动。解法是切完之后显式给 `val_set.dataset` 换成不带增强的 dataset。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 2：拿过拟合 gap 跨配置比较**

见 4.4 节。加了增强之后，训练集准确率的输入变了，这个数就不能和不增强的比。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 3：增强过强，训练集都拟合不了**

`strong` 档实测训练集准确率只有 **86.12%**（不增强是 99.44%）。

如果你看到"训练集准确率上不去"，除了怀疑模型太小、学习率不对，还要**怀疑增强太狠**。判断方法：把 `--level` 换成 `none` 再跑一次 —— 如果训练集准确率立刻上去了，那就是增强的问题。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 4：以为增强一定会涨点**

本章实测：轻增强平均 +0.36pp（区间与不增强重叠），强增强 **-1.59pp**。

**增强的有效性取决于模型本来有没有过拟合。** 第 3 章这个 4 层 CNN 在 MNIST 上本来就只有 0.96% 的 gap，能压的空间很小 —— 所以涨点有限。换个场景，如果模型已经严重过拟合（比如在只有 500 张图的小数据集上训练一个大网络），同一个 `light` 档可能带来好几个百分点的提升。

**"要不要加增强"没有通用答案，得看你的 gap 有多大。**

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 5：增强的 transform 顺序写错**

`RandomRotation` 放 `ToTensor` 后面、`RandomErasing` 放前面 —— 都能跑，但结果和你预期的不同（见 4.3 节的灰块例子）。

记忆口诀：**几何变换在 PIL 阶段（`ToTensor` 前），数值操作在张量阶段（`ToTensor` 后）。**

</blockquote>

## 小结

- **增强 = 给训练集加难度**，让模型见不到两张一样的图，逼它抓本质而不是背题
- **只有训练集增强**。验证集 / 测试集是考卷，改考卷等于毁掉分数。本章把这条件写进了 `get_loaders` 的函数签名，让错误无法表达
- **`transforms` 的顺序有意义**：几何变换（`RandomRotation` / `RandomAffine`）在 `ToTensor` 前，`RandomErasing` 在 `Normalize` 后
- **MNIST 上不能用翻转**：翻转之后标签就错了（图 4-1）。判断任何增强能不能用，只问一句"**变换之后标签还对吗？**"
- **实测三档**（10 epoch，种子 42）：

  | 档位 | 测试集 | 相对不增强 |
  |---|---|---|
  | none | 98.60% | — |
  | light | **99.03%** | +0.43pp |
  | strong | 97.01% | **−1.59pp** |

- **轻增强的涨幅落在噪声边缘**：4 个种子平均 +0.36pp，但区间与不增强重叠。它真正确定的贡献是**推迟了过拟合**（不增强的验证集第 6 轮就平了，轻增强到第 10 轮还在涨）
- **不是所有数据集都适合增强**。本章这个 4 层 CNN 在 MNIST 上本来 gap 就只有 0.96%，可压的空间小；模型过拟合越严重，增强的收益越明显
- 增强有真实代价：**每个 epoch 的耗时大约翻倍**（3.8s → 6.4s）
