# 第 2 章 全连接网络与训练循环

## 本章要解决什么问题

上一章把数据准备好了，这一章第一次真正训练出一个模型。重点有两个：

1. **怎么用 `nn.Module` 描述一个网络** —— 这是后面所有章节（CNN、加 BatchNorm、加 Dropout）共用的写法。
2. **训练循环长什么样** —— 这是全书最核心的一段代码。第 3 到第 8 章会换网络、换优化器、加数据增强，但**这个循环的骨架一行都不会变**。

本章用的网络很朴素（两层全连接），因为它的作用不是拿高分，而是让循环本身看得清楚。

---

## 2.1 为什么先讲全连接

卷积神经网络（CNN）听起来比全连接网络（MLP）高级，为什么还要先讲 MLP？

因为它是最简单的、能说明"神经网络到底在干什么"的结构。全连接层做的事只有一件：

```
输出 = 输入 · 权重 + 偏置
```

就是把输入向量乘一个矩阵、加个偏移。一层全连接就是一个线性变换。堆两层、中间加个非线性函数（ReLU），就成了一个能拟合复杂函数的网络。

本章的网络是 `784 → 256 → ReLU → 10`：

- **784** = 28×28，把一张图**拉直**成向量
- **256** 是中间层宽度（可以调，属于超参数）
- **10** 是输出维度，对应 0–9 十个类别

关键缺陷在"拉直"这一步：一旦拉直，**像素之间的上下左右关系就全丢了**。对模型来说，第 5 个像素和第 6 个像素相邻这件事，和它们在这个 784 维向量里的位置关系毫无区别。而图像识别恰恰极度依赖空间结构 —— 这正是第 3 章卷积要解决的问题。

先记住这个数字：**本章 MLP 的参数量是 203,530**。第 3 章的 CNN 参数量会少一个数量级，但准确率更高。这个对比很有说服力。

## 2.2 `nn.Module`：`__init__` 和 `forward` 各写什么

PyTorch 里定义网络，就是写一个 `nn.Module` 的子类。必须写两个方法：

```python
class SimpleMLP(nn.Module):
    def __init__(self, hidden=256):
        super().__init__()
        self.fc1 = nn.Linear(28 * 28, hidden)

    def forward(self, x):
        return self.fc2(self.relu(self.fc1(x)))
```

**`__init__` 里声明"有哪些零件"。** 带参数的层（`nn.Linear`、`nn.Conv2d`）必须在这里创建并赋给 `self.xxx`。这样做之后，PyTorch 才能：

- 用 `model.parameters()` 一次性拿到所有参数交给优化器
- 用 `model.to(device)` 把所有参数一次性搬到 GPU
- 用 `model.state_dict()` 一次性保存/加载全部权重

**`forward` 里声明"数据怎么流过这些零件"。** 它描述的是计算过程。你**不要自己调用 `forward()`**，而是用 `model(x)` —— 这样 PyTorch 才能顺带挂上钩子（hooks）等机制。

<div class="warn-box">

**⚠️ 常见坑**

**`super().__init__()` 忘了写。**

这是最经典的一个。父类的构造函数负责初始化 `nn.Module` 内部那套记账机制（`_parameters`、`_modules` 等字典）。不调用它，你后面 `self.fc1 = nn.Linear(...)` 时 PyTorch 就没有地方登记，等到调用 `model.parameters()` 时会发现**一个参数都没有**，优化器拿到空列表，训练时静默地什么都不学。

报错信息通常是 `AttributeError: cannot assign module before Module.__init__() call`。看到这个就直接往上看有没有漏掉 `super().__init__()`。

</div>

**反向传播不用你写。** `loss.backward()` 之后怎么求每个参数的梯度，是 autograd 自动完成的 —— 它记录了前向过程中的每一步运算，反向按链式法则推回去。这是 PyTorch 最省事的地方，也是为什么你几乎看不到有人手写梯度公式。

## 2.3 逐行读 `ch02_mlp.py`

### 模型定义

```python
class SimpleMLP(nn.Module):
    def __init__(self, hidden: int = 256):
        super().__init__()
        self.flatten = nn.Flatten()             # (N,1,28,28) -> (N,784)，无参数
        self.fc1 = nn.Linear(28 * 28, hidden)   # 784 -> 256
        self.relu = nn.ReLU()                   # 非线性
        self.fc2 = nn.Linear(hidden, 10)        # 256 -> 10

    def forward(self, x):
        x = self.flatten(x)
        x = self.fc1(x)
        x = self.relu(x)
        x = self.fc2(x)
        return x                                # 返回 logits，不接 softmax
```

`nn.Flatten()` 默认把**第 1 维开始到最后一维**全部展平，所以 `(N, 1, 28, 28)` 变成 `(N, 784)`，第 0 维（batch）保留 —— 这正是我们要的。

### 损失函数与优化器

```python
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9)
```

`criterion` 负责"算错得有多离谱"，`optimizer` 负责"按什么规则改参数"。两者职责完全不同，不要混。

`SGD` 是最基础的优化器，它做的事就是"往梯度的反方向走一步"，步长由 `lr`（学习率）决定。`momentum=0.9` 让它带一点惯性，不容易卡在小坑里。

<div class="warn-box">

**⚠️ 常见坑**

**学习率必须和优化器配套。** 本书实测（同样 10 个 epoch、其他设置全同）：

| 配置 | 测试集准确率 |
|---|---|
| SGD `lr=1e-3`，momentum=0.9 | 94.51% |
| **SGD `lr=0.01`，momentum=0.9（本书采用）** | **97.90%** |
| SGD `lr=0.05`，momentum=0.9 | 98.19% |
| Adam `lr=1e-3` | 97.95% |

同一个网络、同一份数据，只是学习率差了 10 倍，准确率差了 3.4 个百分点。

原因：`1e-3` 是 **Adam 的经典默认值**，不是 SGD 的。Adam 自己会按参数的梯度历史动态调整每一步的实际步长，所以初始值可以很小；SGD 只看当前 batch 的梯度、方向噪声大，需要大 10–50 倍的步长才走得动。

**记住这条规则：换优化器就要重新想学习率。** 第 5 章会把学习率系统地扫一遍。

</div>

### 训练一个 epoch

```python
def train_one_epoch(model, loader, optimizer, criterion, device):
    model.train()
    total_loss, correct, n = 0.0, 0, 0

    for x, y in loader:
        x, y = x.to(device), y.to(device)

        optimizer.zero_grad()          # ①
        logits = model(x)              # ②
        loss = criterion(logits, y)    # ③
        loss.backward()                # ④
        optimizer.step()               # ⑤

        total_loss += loss.item() * y.size(0)
        correct += (logits.argmax(dim=1) == y).sum().item()
        n += y.size(0)

    return total_loss / n, correct / n
```

`logits.argmax(dim=1)` 的 `dim=1` 很关键：`logits` 形状是 `(N, 10)`，我们要在**每个样本的 10 个分数里**挑最大的那个。`dim=1` 就是"沿着类别维取最大"，结果形状 `(N,)`，正好和 `y` 对比。如果写成 `dim=0`，就变成"在每个类别上跨样本取最大"，完全错了。

### 评估

```python
def evaluate(model, loader, device):
    model.eval()
    with torch.no_grad():
        ...
```

## 2.4 训练循环的五步

这五行是本章最需要背下来的东西。每一行都有它存在的理由：

**① `optimizer.zero_grad()` —— 清空旧梯度。**

PyTorch 的梯度是**累加**的，不是覆盖的。不清零的话，这一步算出的梯度会和上一步的叠在一起。实测（同一个输入反复 backward 三次）：

```
不清零，连续 backward 三次的梯度: [0.613979, 1.227958, 1.841938]
```

正好是 1 倍、2 倍、3 倍 —— 第二步是两步梯度之和，第三步是三步之和。

**② `logits = model(x)` —— 前向传播。**

数据流过网络，得到每个类别的未归一化分数。同时 autograd 在背后默默记录计算图，为第 ④ 步做准备。

**③ `loss = criterion(logits, y)` —— 算损失。**

把预测和正确答案比较，得到一个标量。**它必须是标量（单个数字）**，因为 `backward()` 只能对标量求导。

**④ `loss.backward()` —— 反向传播。**

从 loss 出发，按链式法则倒着推，算出**每个参数**的梯度，存进 `param.grad` 里。注意：这一步只**算**梯度，**不改**参数。

**⑤ `optimizer.step()` —— 更新参数。**

优化器读取每个参数的 `.grad`，按自己的规则改参数值。这一步才真正改变模型。

<div class="done-box">

**📌 结论**

④ 和 ⑤ 的分工是这个循环最容易记混的地方：

- `backward()` 负责**算**梯度 —— 它不知道学习率，也不知道优化器是谁
- `step()` 负责**用**梯度 —— 它不知道 loss 是什么

所以你可以自由换优化器（第 5 章会做）而完全不动 `backward()`；也可以换损失函数而不动 `step()`。

</div>

**关于那两行统计代码：**

```python
total_loss += loss.item() * y.size(0)
```

为什么要乘 `y.size(0)`？因为最后一个 batch 可能不满（第 1 章讲过，50000 / 128 的最后一只有 48 张）。如果直接把每个 batch 的 loss 相加再除以 batch 数，那个只有 48 张的 batch 会和 128 张的 batch 权重相同，算出来的平均值就偏了。乘上样本数再统一除以总样本数 `n`，才是真正的"按样本加权平均"。

## 2.5 `train()` / `eval()` 和 `no_grad()`

这三个东西经常一起出现，但作用完全不同，别搞混。

**`model.train()` / `model.eval()` 切换的是"层的行为模式"，不是"要不要算梯度"。**

有些层在训练和推理时的行为**必须不同**：

| 层 | 训练时 | 评估时 |
|---|---|---|
| `Dropout` | 随机丢弃一部分神经元 | 全部保留（并缩放） |
| `BatchNorm` | 用当前 batch 的均值/方差 | 用训练期间累积的全局均值/方差 |

如果评估时忘了 `model.eval()`，Dropout 会继续随机丢弃神经元，BatchNorm 会用当前 batch 的统计量 —— 结果就是**同一个模型每次评估得分都不一样**，而且偏低。本章的 MLP 没有这两层，所以现在看不出区别，但**习惯要从一开始就养成**，第 6 章加了 Dropout 之后忘了它就是灾难。

**`torch.no_grad()` 省的是"记录计算图"的开销。**

实测：

```
默认      : requires_grad=True   grad_fn=AddmmBackward0
no_grad 内: requires_grad=False  grad_fn=None
```

默认情况下，PyTorch 会为每个运算记录它是怎么算出来的（`grad_fn`），这样将来才能反向求导。评估时我们根本不需要反向传播，这些记录纯属浪费内存和时间。`no_grad` 就是把记账关掉。

<div class="tip-box">

**💡 提示**

`train()` 和 `no_grad()` 是两件独立的事，可以随意组合：

- 训练时：`model.train()` + **不**加 `no_grad`（要算梯度）
- 评估时：`model.eval()` + `no_grad`（不要梯度）
- 偶尔有人会写 `model.eval()` 但不加 `no_grad` —— 结果对了，但白白浪费显存

</div>

## 2.6 `CrossEntropyLoss` 吃的是 logits

这是新手最容易搞错、后果又很隐蔽的一个点。

`nn.CrossEntropyLoss` 内部 = **`log_softmax` + 负对数似然**。也就是说，**它自己会做 softmax**。所以你喂给它的必须是**没做过 softmax 的原始分数（logits）**。

实测对比（三个类别的 logits，正确答案是第 0 类）：

```
直接喂 logits        : 0.417030     <- 正确用法
先 softmax 再喂      : 0.802121     <- 错误，损失凭空变大
手算 log_softmax+NLL : 0.417030     <- 与第一行完全一致，证明 CE 内部就是这么算的
```

**为什么"先 softmax 再喂"是有害的，而不只是数值偏大？**

softmax 会把输出压到 0–1 之间，而且当某个分数明显占优时，softmax 的输出会**极度接近 0 或 1**（饱和）。饱和区域的梯度接近于零 —— 也就是说，模型明明预测错了，梯度却小得推不动它。

所以这个错误的症状很典型：**loss 比正常值大、下降得慢、准确率上不去**，而你在代码里完全看不出哪里不对，因为每一行语法都对。

<div class="done-box">

**📌 结论**

- 用 `nn.CrossEntropyLoss` → 模型**最后一层不要接 softmax**，直接输出 logits
- 想拿到概率（比如要展示置信度）→ 推理时对 logits 手动调 `torch.softmax(logits, dim=1)`
- 目标 `y` 给的是**类别编号**（`int64`），不是 one-hot。这也是第 1 章强调它 `dtype` 的原因

</div>

## 2.7 PyTorch 默认怎么初始化权重

你没写任何初始化代码，那 `nn.Linear` 的初始权重是什么？实测：

```
weight 范围 : [-0.035714, 0.035714]
bias   范围 : [-0.035493, 0.035089]
理论界 ±1/sqrt(784) = ±0.035714
```

结论：**默认是从 `[-1/√fan_in, 1/√fan_in]` 的均匀分布里随机取的。** 本例 `fan_in = 784`，所以界是 ±0.0357。

（技术细节：这实际上等价于 `kaiming_uniform_` 配 `a=√5`，其 gain 恰好是 `√(2/(1+5)) = 0.5774`，代进公式算出的界正是 `1/√fan_in`。你不用记这个推导，记住"PyTorch 默认初始化已经够用"就行。）

**为什么初始化这么重要？** 如果全部初始化为 0，所有神经元的输出完全一样、梯度也完全一样，它们会永远保持同步 —— 相当于一层里只有一个神经元在工作。这就是第 3 章要演示的 `init_mode="zeros"` 会训练失败的原因。

实践中两个都要看，但**决定早停（什么时候停止训练）时，通常以验证集准确率为准**。

</div>

**这个 gap 就是第 6 章要处理的问题。** 到时候会加 Dropout、加数据增强，看能不能把 gap 压下去。不过要先说清楚：**在这个任务上，单纯堆正则化收益有限**，因为 MLP 的瓶颈不在过拟合，而在它压根看不见空间结构。真正的大幅提升要靠第 3 章的卷积。

## 2.9 常见坑

<blockquote class="warn">

**⚠️ 常见坑 1：忘了 `zero_grad()`**

梯度会累加（2.4 节实测过 1×/2×/3×）。忘了清零的症状是：**loss 一开始就很大，或者直接变成 NaN 然后发散**，因为梯度等于把最近 n 步的梯度全加起来，更新幅度越来越大。

有意思的是，忘清零不会报错、不会崩溃，只是训练效果差。这类"静默错误"最难查。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 2：在 `CrossEntropyLoss` 前面加了 softmax**

见 2.6 节。症状是 loss 偏大、下降慢、准确率上不去，但代码语法完全正确。

**记住判断方法：** 如果你的模型 `forward()` 最后一行是 `softmax`，且损失函数是 `CrossEntropyLoss`，那你写错了。二分类用 `BCEWithLogitsLoss` 时同理 —— 名字里的 "WithLogits" 就是在提示"别自己加 sigmoid"。

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 3：评估时忘了 `eval()` / `no_grad()`**

- 忘 `eval()`：有 Dropout / BatchNorm 时结果不可复现且偏低
- 忘 `no_grad()`：结果正确，但显存浪费、速度变慢

本章的 MLP 没有这两层，所以忘 `eval()` 暂时看不出问题 —— **但这是运气，不是正确**。等到第 6 章加了 Dropout，同样的代码就会出问题，而那时你早就忘了是这里埋的雷。

**养成习惯：写 `evaluate()` 时，`model.eval()` 和 `with torch.no_grad():` 一起写。**

</blockquote>

<blockquote class="warn">

**⚠️ 常见坑 4：`CUDA_VISIBLE_DEVICES=""` 不能屏蔽 GPU**

想强制用 CPU 跑一遍对比速度时，很多人会写：

```bash
CUDA_VISIBLE_DEVICES="" python ch02_mlp.py --smoke
```

**这在 Windows 上无效** —— 空字符串会被当成"没设置"，`torch.cuda.is_available()` 依然返回 `True`。本书实测：

```
CUDA_VISIBLE_DEVICES=""     -> is_available = True    <- 没屏蔽掉
CUDA_VISIBLE_DEVICES="-1"   -> is_available = False   <- 正确
CUDA_VISIBLE_DEVICES="none" -> is_available = False   <- 也可以
```

要用 `-1`。

</blockquote>

## 小结

- `nn.Module` 子类写两个方法：`__init__` 声明零件，`forward` 声明数据怎么流
- 训练循环五步：`zero_grad → forward → loss → backward → step`。`backward` 算梯度，`step` 用梯度
- 梯度是**累加**的，所以 `zero_grad()` 不能省
- `model.train()` / `model.eval()` 切的是层的行为模式；`no_grad()` 省的是计算图记录。两者独立
- `CrossEntropyLoss` 内部含 softmax，**喂 logits**，最后一层不要接 softmax
- 学习率必须和优化器配套：SGD 用 0.01，Adam 用 1e-3。**换优化器就要重想学习率**
- 本章结果：MLP 参数量 203,530，测试集 **97.87%**。曲线显示从第 3 个 epoch 起验证 loss 不再下降，过拟合 gap 最终扩大到 1.82 个百分点
